⚙️ Encoding Pipeline — compress hard, keep quality

Compression happens server-side (a browser can't transcode uploads). When you add a backend, run every master file through per-title encoding: quality-targeted CRF instead of fixed bitrates, so simple scenes shrink dramatically and complex scenes keep their bits. Recommended ladder:

# H.265 — visually lossless, ~50% smaller than H.264 ffmpeg -i master.mp4 -c:v libx265 -preset slow -crf 21 -tag:v hvc1 \ -c:a aac -b:a 160k out_h265.mp4 # AV1 — best compression for web delivery ffmpeg -i master.mp4 -c:v libsvtav1 -preset 6 -crf 30 \ -c:a libopus -b:a 128k out_av1.webm # Adaptive streaming ladder (HLS): 1080p / 720p / 480p ffmpeg -i master.mp4 -filter_complex \ "[0:v]split=3[v1][v2][v3];[v1]scale=-2:1080[v1o];[v2]scale=-2:720[v2o];[v3]scale=-2:480[v3o]" \ -map "[v1o]" -map "[v2o]" -map "[v3o]" -map a:0 -c:v libx265 -crf 21 \ -c:a aac -b:a 128k -f hls -hls_time 6 -master_pl_name master.m3u8 stream_%v.m3u8

Keep the untouched master in cold storage; serve the compressed ladder. Validate with VMAF ≥ 95 before replacing any rendition.
